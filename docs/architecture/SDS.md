# Software Design Specification (SDS) - Note Taking App

Status: derived from source at commit `9d46615` (branch `main`). Every statement below was checked against the repository; where a claim could not be verified at runtime it is marked "(static reading)". Paths are relative to the repo root; `file:line` cites refer to that commit.

Related: [ADR index](adr/README.md), `CLAUDE.md` (conventions), `openspec/specs/*` (21 capability specs), `openspec/changes/archive/*` (16 archived changes).

## 1. Scope and system context

A full-stack, single-tenant-per-user note-taking application: registration/login, password reset by console-logged OTP, rich-text notes (TipTap/ProseMirror JSON) with tags, pagination/sorting/tag filtering, PostgreSQL full-text search with highlighting, public share links, version history with restore.

Explicitly out of scope (`openspec/config.yaml`, `CLAUDE.md`): real-time collaboration, attachments, OAuth/social login, folder nesting, external search, real email delivery.

### 1.1 Monorepo layout (`pnpm-workspace.yaml`: `apps/*`, `packages/*`)

| Workspace         | Role                                                                                                               |
| ----------------- | ------------------------------------------------------------------------------------------------------------------ |
| `apps/api`        | Express 5 REST API (TypeScript, run with `tsx`)                                                                    |
| `apps/web`        | React 19 + Vite SPA (also holds Playwright E2E under `apps/web/e2e`)                                               |
| `packages/shared` | Zod schemas + inferred types for every request/response contract                                                   |
| `packages/db`     | Prisma schema, migrations, generated client re-export (`packages/db/src/index.ts`)                                 |
| `packages/config` | Shared ESLint/Prettier/tsconfig/Vitest config, custom `feature-structure` lint rule, commitlint ticket-rule plugin |

### 1.2 Responsibilities

- **Frontend**: routing and route guards, forms, server-state caching, editor with debounced autosave, session (access token) held in memory, transparent 401 -> refresh -> retry. No business rules beyond UX.
- **Backend**: authentication/authorization (ownership checks), validation, business rules (title derivation, tag ownership, snapshot-on-update, share-link lifecycle), persistence, error normalization, OpenAPI docs (non-production).
- **Database (PostgreSQL 16)**: system of record; hosts the generated `tsvector` column + GIN index, partial/functional indexes hand-written in migrations, FK cascades.

## 2. Architecture and request flow

```
Browser (React SPA, :5173)
  -> apiFetch (Bearer access token, cookies included)            apps/web/src/lib/api-client.ts
  -> Express app (:4000)                                          apps/api/src/app.ts
       helmet -> cors -> pino-http -> express.json(1mb) -> cookie-parser -> global rate limit
       -> router (per feature)
            [requireAuth] -> [validate(zod, body|params|query)] -> asyncHandler(controller.method)
            controller (HTTP <-> DTO mapping) -> service (rules, transactions) -> repository (Prisma)
       -> notFoundHandler -> errorHandler  (JSON ErrorResponse)
  -> PostgreSQL via Prisma Client                                 packages/db
```

Middleware order is `apps/api/src/app.ts:36-47` (helmet, cors with `credentials: true`, pino-http, `express.json({limit:"1mb"})`, cookie-parser, global `express-rate-limit`), then routers (`app.ts:55-68`), then `notFoundHandler` / `errorHandler` (`app.ts:72-73`). `notes-search` is deliberately mounted before `notes` so `GET /notes/search` is not captured by `GET /notes/:id` (comment and mount order in `app.ts`, search router before notes router).

Composition is manual constructor injection inside each `createXRouter(prisma, env)` factory; `createApp(env, {logger, prisma, extraRoutes})` takes injectable collaborators for tests (`app.ts:25-29`). `server.ts` parses env (fail-fast, exit 1), listens, and wires graceful shutdown (`shutdown.ts`: stop accepting, sweep idle sockets every 50 ms, force-close after 10 s default).

## 4. Authentication and authorization

- **Access token**: JWT HS256, 15 min (`auth/access-token.ts:4-5`), claims `sub`, `jti`, `iat`, `exp`; secret `JWT_ACCESS_SECRET`. Verified by `requireAuth` from the `Authorization: Bearer` header, which sets `req.user = {id}` (`middleware/require-auth.ts`).
- **Refresh token**: 32 random bytes base64url (`crypto/secure-token.ts`), 7-day TTL (`auth-router.ts:26`). Only an HMAC-SHA256 of the token (keyed with `JWT_REFRESH_SECRET`) is persisted in `RefreshToken.tokenHash` (`auth/refresh-token.ts`). Delivered as cookie `refresh_token`: `httpOnly`, `sameSite: "lax"`, `secure` only when `NODE_ENV=production`, `path=/auth` (`auth-router.ts:28-46`).
- **Rotation and reuse detection** (`auth/session-service.ts`, `auth/refresh-token-repository.ts`): each refresh creates a child token in the same `familyId`, marks the parent `revokedAt`/`replacedByTokenId` inside one transaction guarded by `revokedAt: null` (lost races return null and delete the orphan child, `refresh-token-repository.ts:71`). Presenting an already-revoked token revokes the whole family. Expired tokens are rejected. Logout revokes the presented token.
- **Passwords/OTP**: bcrypt (cost 12 per test comments) for passwords and OTP hashes; 6-digit OTP from `crypto.randomInt`, 10 min TTL, previous unconsumed OTPs invalidated, single-use enforced by a guarded `updateMany` inside a transaction (`auth/auth-service.ts`). Anti-enumeration: dummy bcrypt hash compare and equal DB round-trips for unknown emails; generic responses.
- **Authorization** is ownership-scoped, not role-based: every note/tag/share/history query includes `userId` and `deletedAt: null` (`NotesRepository.findOwned/updateOwned/softDeleteOwned`; `assertOwnsNote` in sharing and history services). Foreign or missing resources return 404 (no existence leak). Tag ids on notes are checked for ownership (`notes-service.ts:71`).
- **Web side**: access token only in Zustand memory (no `localStorage`/`sessionStorage` use; verified by grep). On app boot `AppProviders` calls `refreshSession()` (cookie-based) before rendering (`providers/AppProviders.tsx`). `apiFetch` retries once after a single-flight refresh on 401 (`lib/api-client.ts`); `skipRefresh`/`skipAuth` flags for auth and public endpoints.

## 5. Data model

Source: `packages/db/prisma/schema.prisma` (Prisma 5.22, PostgreSQL, client generated to `packages/db/generated/client`).

```
User 1--* RefreshToken        (RefreshToken self-relation: replacedBy / replacedFor, familyId)
User 1--* PasswordResetOtp
User 1--* Note  1--* NoteVersion   (onDelete: Cascade)
                Note 1--0..1 SharedNote  (noteId unique, onDelete: Cascade)
                Note *--* Tag via NoteTag (composite PK; tag FK onDelete: Cascade)
User 1--* Tag
```

| Model              | Notable fields / constraints                                                                                                                                                                                                                                                      |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `User`             | `email` unique (normalized lower-case in service), `passwordHash`                                                                                                                                                                                                                 |
| `Note`             | `content Json` (ProseMirror doc), `title` (derived), `searchText` (derived plain text), `searchVector Unsupported("tsvector")?` (generated column, hidden from Prisma Client), `deletedAt` soft-delete; `@@index([userId, deletedAt])` approximating a hand-written partial index |
| `Tag`              | `name`, `color` default `#64748B`; `@@unique([userId, name])` approximating a hand-written case-insensitive unique index on `(userId, lower(name))`                                                                                                                               |
| `NoteTag`          | PK `(noteId, tagId)`, `@@index([tagId])`; note FK has no cascade (notes are only soft-deleted)                                                                                                                                                                                    |
| `NoteVersion`      | `title`, `content` snapshot of the pre-update state; `@@index([noteId, createdAt])`                                                                                                                                                                                               |
| `SharedNote`       | `token` unique (stored plaintext, intentional - see `sharing-service.ts` comment), `viewCount`, `expiresAt?`                                                                                                                                                                      |
| `PasswordResetOtp` | `otpHash`, `expiresAt`, `consumedAt?`, `@@index([userId])`                                                                                                                                                                                                                        |
| `RefreshToken`     | `tokenHash` unique, `familyId`, `revokedAt?`, `replacedByTokenId?` unique, `@@index([familyId])`, `@@index([userId])`                                                                                                                                                             |

Migrations (`packages/db/prisma/migrations`, in order):

1. `20260926103822_add_user_auth`
2. `20260926125556_add_password_reset_otp`
3. `20260926144918_add_note` (hand-edited partial index `Note_userId_active_idx ... WHERE "deletedAt" IS NULL`)
4. `20260926165154_add_tag` (hand-edited functional unique index)
5. `20260927011800_notetag_tag_cascade`
6. `20260927120000_add_note_search` (generated `tsvector` column + GIN index `Note_searchVector_idx`)
7. `20260927120000_add_shared_note` (same timestamp prefix as #6; applied in lexical name order)
8. `20260927150000_add_note_history`

Because items 3, 4 and 6 hold constructs Prisma's DSL cannot express, `prisma migrate dev` will report drift; the schema comments instruct developers to cancel the offered fixup (`schema.prisma:56-66,82-93`). Migrations are applied with `prisma migrate deploy` in CI and in the API container start command.

Retention reality: note rows are never hard-deleted. `NoteVersion` rows older than 30 days are purged lazily, only when the same note is next updated with changed content (`notes-history-repository.ts:43`). There is no job that purges soft-deleted notes after 30 days (see section 11).

## 6. Validation and error handling

- **Validation**: `validate(schema, "body"|"params"|"query")` (`middleware/validate.ts`) runs `safeParse`, replaces the request part with parsed data (query via `Object.defineProperty` because Express 5 `req.query` is getter-only), and fails with `AppError("VALIDATION_FAILED", 422, ..., issues)`. Environment variables are validated at boot with Zod (`config/env.ts`; required: `DATABASE_URL`, `CORS_ALLOWED_ORIGINS`, `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`; tunables for global and share rate limits). Notes content schema bounds ProseMirror nesting depth (`MAX_CONTENT_DEPTH = 50`), tag ids (<=50), page size (<=100), tag filter (<=10), search query length (200).
- **Errors**: `AppError(code, status, message, details?)` (`errors/app-error.ts`); `asyncHandler` forwards rejected promises; `errorHandler` (`middleware/error-handler.ts`) maps `AppError`, stray `ZodError` (400), objects with `status`/`statusCode` (`REQUEST_ERROR`, e.g. body-parser errors), and everything else to a generic 500 while logging `err` via `req.log`. Prisma P2002/P2003 are translated in services via `errors/prisma-errors.ts`.

## 8. Frontend architecture (`apps/web`)

- **Stack**: React 19, Vite 6, TypeScript, TanStack Query 5, Zustand 5, TipTap 2 (`StarterKit`), react-router 7 (data router), react-hook-form + zod resolvers, Tailwind 4, shadcn/ui (Radix) components in `src/components/ui`.
- **Structure**: `src/features/<feature>/{api,hooks,components,lib}` for `auth, notes, notes-search, notes-history, sharing, tags, health`; shared `lib/`, `components/`, `routes/`, `providers/`, `store/`. A custom ESLint rule `local/feature-structure` rejects files directly under `src/` outside an allow-list (`packages/config/src/structure-rule.js`, wired in `eslint.config.js`).
- **Routes** (`routes/router.ts`): `/` and `/notes/:noteId` behind `RequireAuth`; `/shared/:token` public; `/register`, `/login`, `/forgot-password`, `/reset-password` behind `RequireGuest`; `*` not-found. Note editor and shared viewer are code-split via `lazy` because TipTap is large. Error boundaries: top-level (`main.tsx`) and route-level (`RouteErrorFallback`).
- **Server state**: TanStack Query with defaults `retry: 1`, `staleTime: 30s`, `refetchOnWindowFocus` (`lib/query-client.ts`). Hooks such as `useNotesQuery` (keyed on sorted params, `keepPreviousData`), `useTagsQuery`, `useSearchQuery`, `useNoteVersions`, `useRestoreNoteVersion`, `useShareLink`, `useSharedNoteQuery`. All HTTP goes through `apiFetch` in `lib/api-client.ts`; the only raw `fetch` calls are there (`api-client.ts:71,110`, verified by grep).
- **Client state**: Zustand `session-store` (status, user, in-memory access token) and `ui-store` (sidebar flag).
- **Editor/autosave** (`features/notes/hooks/use-autosave.ts`, `components/NoteEditorPage.tsx`): TipTap `onUpdate` -> `scheduleSave` (1500 ms idle debounce) -> single-flight `useMutation` PATCH; states `idle|pending|saving|saved|error`; `saveNow` for discrete actions (tag toggles), `flushPending` before version restore, flush on unmount, `beforeunload` guard while dirty, retry on error. The note title is stored as the first block of the document and split/combined client-side (`note-content-split.ts`); the server derives `title` from the first node (`deriveTitle`).
- **Contracts**: web imports DTO types from `@note-taking-app/shared`; `NormalizedApiError` in `lib/api-client.ts` is a web-only wrapper type.

## 10. Deployment, constraints and integration points

- `docker-compose.yml`: `postgres:16` (volume, healthcheck), `api` (built from `apps/api/Dockerfile`; runs `prisma migrate deploy` then `tsx src/server.ts` with `NODE_ENV=production`, so Swagger is off and the refresh cookie is `secure`), `web` (built from `apps/web/Dockerfile`, `VITE_API_BASE_URL` baked at build time, served on 4173 mapped to 5173). Local-only default JWT secrets are provided by compose fallbacks.
- Constraints: Node >=22 <23, pnpm 9.15 (`package.json` engines/packageManager); workspace packages export raw `.ts` (hence `tsx` at runtime, `apps/api/Dockerfile` comment); Prisma client output at `packages/db/generated/client` (git-ignored).
- Integration points: PostgreSQL only. No outbound integrations (no email, no external search). OTP delivery is a console line (`auth-router.ts:116`) that E2E parses from `.api.log`.
- Operational scripts: `apps/api/src/scripts/backfill-search-text.ts` (idempotent backfill of `Note.searchText`).
